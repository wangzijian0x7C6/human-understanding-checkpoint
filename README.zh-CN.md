# 人类理解检查点

[English](README.md) | 中文

一个 Agent Skill：在会改变行动的模型输出被用于后续决策、交接、转发或重要行动前，先取得可用的理解证据。

它**不是审批弹窗**，也**不是教学系统**。它是一套面向人–LLM 协作的通用“理解状态协议”：找出最小关键点，取得可用证据，只修复理解缺口，并在正确的边界继续工作。

> [!NOTE]
> 本项目目前是研究预览版。它只能提供对话中的理解证据，不能证明人的内在状态，也不构成法律同意、医疗行为能力或专业胜任力的证明。

## 为什么需要它

几乎所有 agent harness 都为**操作**建立了 human-in-the-loop（Human-in-the-Loop，HIL）：执行前需要人类判断通过。但 HIL 不止于审批——它的本质是让人类判断成为流程的守门节点。在**信息**层面，这个节点是缺失的：对话中的结论、模型产出的文件，往往不经任何人类认知环节就被采信、复述、转发或写进文档。错误操作通常当场暴露，错误信息则会静默传播——它一旦被引用，就带上了引用者的背书。

这个 skill 把 HIL 延伸到信息维度：在信息即将驱动决策或被转发之前，要求人类拿出可验证的理解证据，而不是一声“知道了”。通过 operation 靠授权，通过 information 靠理解。

模型输出经常被直接复制到决策、文档或消息里，而人可能没有意识到其中的假设、不确定性或承诺。礼貌地回复“明白了”并不能说明关键内容能够被正确应用。

这个 skill 只在误解可能改变下一步时，加入与风险相称的检查点。

| 场景 | 常见失败 | 检查点的处理 |
|---|---|---|
| 转发 AI 撰写的建议 | 估算结果被包装成人认可的事实 | 定稿前让发送者解释关键主张和承诺 |
| 后续工作依赖先前区别 | 把“明白”当成长期有效的证据 | 结合真实下一步验证，并记录成立条件 |
| 用户理解但不同意 | 模型反复警告或阻止继续 | 将权衡标为已确认，并尊重知情选择 |
| 已确认的假设发生变化 | 在新情境中继续沿用旧信心 | 只重新验证受影响的主题，而不是重考全部内容 |
| 模型推算的数字尚未验证 | 对话中的估算被当成已审计结果 | 把理解状态和内容有效性分开，并明确剩余验证工作 |
| 模型凭记忆给出的引用、政策或“已完成”声明 | 自信但错误的引用、或没有工具结果支撑的执行声明被直接采信 | 标注为未验证，提供确定性核查方法，并确认用户的理解与用途 |

完整的前后对比例子见[价值案例](docs/value-cases.zh-CN.md)。

## 工作方式

1. 找出最多三个可能改变用户下一步行动的命题。
2. 选择足够但最轻的强度：`light`、`active` 或明确要求的 gated 模式。
3. 提出一个应用、复述、后果、辨析或预测问题。
4. 将证据判断为 `confirmed`、`partial`、`misconception` 或 `unverified`。
5. 继续、精准修复后复查，或只暂停依赖该理解的步骤。

已经确认的理解会作为带条件的主题状态复用；一般只在事实或假设变化、用户后续自相矛盾、时间或上下文明显推进、或所需精度提高时才重新验证。

理解状态与内容有效性分别记录。同一套“未验证声明”处理覆盖五类已知的 LLM 可靠性局限：非正式的定量推理、可查证的引用（文献、法条、条款号、API 名称）、可能早于知识截止日期的时效性事实、没有工具结果支撑的执行声明，以及从图片、PDF、表格或长文档中提取的细节。检查点确认的是用户理解了声明的状态及其用途，而不是声明本身的正确性。

## 模式

- `adaptive`：默认模式；只有后果值得时才介入。
- `always`：每当实质性回复引入新的决策相关概念时进行检查。
- `gate`：理解未确认前不执行依赖步骤；只在用户明确要求或其他规则要求时使用。


## 初步评估

仓库包含一套成对、盲测评估工具，共有 23 个固定对话案例。它测量的是可观察的 **Agent 行为**，例如检查点校准、证据质量、进度控制、硬失败和问题负担；它不测量人的真实理解。

两次各含 6 个案例的内部 pilot 都显示了正向趋势，但每个条件只生成一次，只使用了一个同模型家族的评审，而且没有记录确切模型版本。两次精确成对符号检验在统计上均不显著（各为 `p = 0.25`），因此不能把它们引用为“这个 skill 提高了人的理解”的证据。

评估工具、评分标准、案例与 pilot 原始产物继续公开，便于复现。详见[评估设计](benchmark/BENCHMARK.md)和[初步 pilot 报告](benchmark/PILOT_RESULTS.md)。未来的效果主张需要新的密封保留集、更强基线、多次生成，以及独立或人工评审。

## 相关工作
